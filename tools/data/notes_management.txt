# 誤答の解説（マネジメント系）

## qa8f1292cef
V字モデル :: 開発の各工程とテストの各工程を対応させたモデル。サブシステムごとに繰り返す方式ではない。

## q0dc36c49b5
最初にすべての要件を確定させ、その後は変更しない :: ウォーターフォールモデルの考え方。アジャイルは変化を歓迎する。
詳細な設計書をすべて作成してから開発に着手する :: ウォーターフォール型の進め方。アジャイルは動くソフトウェアを重視する。
テストは開発の最後にまとめて一度だけ行う :: アジャイルでは短いサイクルごとにテストを繰り返す。

## q8786590fd2
XP（エクストリームプログラミング） :: ペアプログラミングやテスト駆動開発などの実践（プラクティス）を重視するアジャイル手法。スプリントやスクラムマスターの役割はない。
ウォーターフォール :: 工程を順番に進める開発モデルで、アジャイル手法ではない。

## q514a5386fb
継続的インテグレーション :: コードの変更を頻繁に統合し、自動でビルドやテストを行う実践。

## q4ab0514ee4
リエンジニアリング :: 既存のシステムを解析し、再設計して作り直すこと。外部から見た動作も変わりうる。
デバッグ :: プログラムの誤り（バグ）を見つけて修正する作業。動作を正しく変えるもの。

## q07cee7e850
フォワードエンジニアリング :: 設計情報から順方向にプログラムを作成する、通常の開発の流れ。

## qf22291e9e6
アジャイル :: 短いサイクルで開発を繰り返す開発手法。開発と運用の連携そのものを指す用語ではない。

## qffeb902462
負荷テスト :: システムに大量の処理をかけて、性能や耐久性を確認するテスト。

## qdda1f7c567
単体テスト :: モジュール単位で行うテストの段階のこと。テストケースの作り方（手法）ではない。
ペネトレーションテスト :: 実際に攻撃を試みて、システムのセキュリティ上の弱点を確認するテスト。

## q2a1145c8f3
1, 50, 100 :: 有効範囲内の値だけで、無効になる境界の外側（0と101）を確認していない。
−1, 50, 101 :: 境界のすぐ内側（1と100）と、すぐ外側の0が含まれていない。
10, 20, 30 :: 境界付近の値がまったく含まれていない。

## q38ca090c07
結合テスト :: 複数のモジュールを組み合わせて、インタフェースが正しく動くかを確認するテスト。
受入れテスト :: 発注者が要件どおりかを確認する最終段階のテスト。
単体テスト :: モジュール単位で正しく動作するかを確認するテスト。

## qc4a6c61156
単体テスト :: 開発者がモジュール単位で行うテスト。
結合テスト :: 開発者がモジュールを組み合わせて行うテスト。
システムテスト :: 開発者側がシステム全体として要件を満たすかを確認するテスト。発注者が行う受入れテストの前に行う。

## qa3ae3151d9
結合テスト → 単体テスト → 受入れテスト → システムテスト :: 単体テストが先。また受入れテストは最後に行う。
システムテスト → 単体テスト → 結合テスト → 受入れテスト :: システム全体のテストは単体・結合テストの後。
受入れテスト → システムテスト → 結合テスト → 単体テスト :: 順序が完全に逆。小さな単位から大きな単位へ進める。

## q5af44e9d55
単体テスト :: V字モデルでは詳細設計（プログラム設計）に対応する。
結合テスト :: V字モデルでは設計（ソフトウェア設計）に対応する。
コードレビュー :: プログラムの記述を人の目で確認する活動で、テスト工程ではない。

## qd829cc8e97
デバッガ :: プログラムの誤りを見つけるための支援ツール。

## q007de50ae7

デバッグ :: 見つかったバグの原因を突き止めて修正する作業。
